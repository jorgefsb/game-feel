# Documentación portable para agentes

[Español](REPOSITORY-DOCUMENTATION.md) · [English](REPOSITORY-DOCUMENTATION.en.md)

1. Lee README y las guías de integración, arquitectura, privacidad y roadmap antes de editar. Verifica versión y hechos con el código real. Guías vigentes nuevas o editadas necesitan contraparte ES/EN, enlaces mutuos y comandos/identificadores literales. No reescribas CHANGELOG ni registros históricos.
2. README contesta qué, para quién, por qué, cómo, cuándo y dónde; después estado, requisitos, costo/licencias, privacidad, límites y ayuda. La primera acción humana va antes de la instalación técnica. No prometas que una biblioteca se instala sola, ni conviertas propuesta o demo en producción.
3. Usa el [brandkit oficial](https://brandkit.jorgesuarez.com.mx/) y [aviso de assets](ASSET-NOTICE.md). No dependas de rutas privadas, GBrain, credenciales o esta máquina. La gramática compartida es firma oficial pequeña arriba a la izquierda, nombre claro Outfit 700, beneficio Inter 400, negro/naranja, demostración real a la derecha. Rasteriza con fuentes oficiales para GitHub. Nada de logos reinventados, neón ni gradientes decorativos. Texto oscuro sobre naranja.
4. Papacito Juice exige Moki real autorizado, sin espejar ni inventar poses; Game Feel genérico no exige ni recibe mascota como dependencia. Empresas conservan su identidad. Los assets de marca no son MIT. No versionar WEBP originales, fuentes descargadas ni vendor.
5. Usa capturas/grabaciones reales y proporcionales a la tarea, sin datos privados. Añade captions VTT y transcripción descriptiva ES/EN; etiqueta datos ficticios. Si la grabación no tiene voz, no inventes una transcripción hablada. H.264 si editas video. No prometas rendimiento universal ni resultados de negocio sin medir.
6. Antes de cambiar: `git status --short`, registra HEAD y crea ref de respaldo local. No cambies `src/`, `vendor/`, pins, tests, runtime, ejemplos ni versiones para arreglar documentación. No publiques sin permiso separado.
7. Ejecuta `npm run verify`, `npm test`, `npm run test:browser`. Comprueba enlaces, paridad ES/EN, seis preguntas, hashes de assets, dimensiones y `ffprobe`. Renderiza Markdown fiel con medios locales a 1280 y 375 px, inspecciona capturas y overflow. Compara runtime/vendor con el baseline byte a byte. Registra evidencia en `reports/docs-brandkit-verification.json`; no inventes resultados ni cambies asserts. Reporta bloqueos exactos.
8. Entrega commits locales, ramas, paths de muestras, resultados y estado Git. No push, tags, release ni deploy como efecto secundario de documentar. Para QA local usa `qa/`, ya ignorado, y apaga los servidores al terminar.
